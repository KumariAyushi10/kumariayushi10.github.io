02 · A/B TEST ANALYSIS · CHECKOUT EXPERIMENT
View repository ↗

NovaCart Checkout A/B Test

A statistical analysis of a simulated 3-week A/B test on a one-click checkout flow for NovaCart, a fictional e-commerce brand. 20,000 synthetic user sessions are split into Control and Treatment groups, then measured on conversion rate, average order value, cart abandonment, checkout time and revenue per session using proper hypothesis testing rather than a simple before/after comparison.

Python SciPy SQL SQLite Jupyter Excel Hypothesis Testing Z-Test / T-Test
20,000user sessions analyzed
~50/50Control vs. Treatment split
+2.1ppbuilt-in conversion lift
95%confidence interval on lift

Key findings

The new checkout converts better.

A two-proportion z-test shows the Treatment group's conversion rate — around 13% versus roughly 10.7% for Control — is significantly higher than the baseline flow.

Mobile sees the biggest lift.

The treatment effect was deliberately weighted to boost mobile conversion the most, and the segment breakdown by device confirms mobile users respond most strongly to the simplified flow.

Order value and speed both improve.

A Welch's t-test on order value alongside checkout-time comparisons shows the one-click flow modestly raises AOV while shortening time to purchase.

Methodology

  • Generate 20,000 sessions with a documented random process.
  • Aggregate metrics by group and segment in SQL.
  • Run a two-proportion z-test on conversion rate.
  • Run a Welch's t-test on order value.
  • Build a live-formula Excel dashboard (SUMIFS/COUNTIFS).

View repository ↗

Superstore Retail Analytics

An end-to-end analysis of the Sample Superstore dataset using Python. The project combines customer segmentation, retention analysis, seasonality, Pareto analysis and product profitability to turn thousands of retail transactions into business recommendations.

Python Pandas NumPy Scikit-learn Matplotlib Seaborn RFM K-Means Cohort Analysis
9,994order line items
5,009orders analyzed
793customers
2014–2017analysis period

Key findings

Discounts can destroy margin.

Profit margin is about 30% at 0% discount and declines as discounts increase, becoming negative at 21%+ discount.

Revenue can hide product problems.

Tables and Bookcases generate meaningful revenue but are unprofitable overall in the dataset.

Revenue is concentrated.

8 of 17 sub-categories contribute roughly 80% of total revenue, giving the business a clear prioritization opportunity.

Business recommendations

  • Set a disciplined discount ceiling.
  • Review pricing and costs for loss-making categories.
  • Give high-value customers targeted VIP treatment.
  • Run win-back campaigns for at-risk customers.
  • Investigate the early cohort-retention drop.
04 · CREDIT RISK & PORTFOLIO ANALYSIS
View repository ↗

Loan Portfolio Analysis

A SQL-only analysis of the public Lending Club loan dataset, built entirely in MySQL. The project stages a messy 140+ column real-world CSV into a clean, properly-typed table, then answers portfolio, risk and borrower-profiling questions using window functions, views and reusable stored procedures for on-demand reporting.

SQL MySQL MySQL Workbench Stored Procedures Window Functions Views Data Cleaning
140+raw source columns cleaned
4analysis sections
3reusable stored procedures
DENSE_RANKstate risk ranking view

What the analysis answers

Portfolio composition.

Totals, grade and purpose breakdowns, and the top states by loan volume give a first read on how the book is built.

Default risk by state.

A DefaultRateByState() procedure and a ranked state_risk_ranking view surface which states and grades carry the most risk.

Borrower profiling.

Income by home ownership, verified vs. non-verified borrowers, and debt-to-income patterns are compared via a LoanProfile() lookup procedure.

Data pipeline

  • Stage the raw CSV as text into raw_loans.
  • Cast and clean into a typed loans table.
  • Guard blanks with NULLIF before casting.
  • Strip "%" from interest rate before conversion.
  • Serve any state via a one-call StateDashboard().
